# 个人差旅报销 App 需求说明

版本：V1.0 需求草案

## 1. 产品定位与已确认范围

面向个人使用的安卓本地工具，按出差批次记录个人垫付的费用、整理支付截图、生成报销材料，并跟踪报销到账。

已确认的要求：

- 主要使用平台为安卓。
- 单人、本地使用，无需注册和登录，核心功能离线可用。
- 按出差批次管理，每个批次包含多笔账单，并具有多个管理状态。
- 实际提交报销前，录入费用、整理材料和准备提交统一归属“记录中”状态。
- 已提交批次支持继续编辑账单并重新提交，修改情况通过账单提醒显示，不另设批次状态。
- 公司报销以支付截图为凭证；发票是可选附件。
- 第一版附件仅支持图片，发票也可以作为图片添加。
- 一笔账单可以关联多张图片，费用按账单计算，不按图片数量计算。
- 每个批次可以导出 Excel、Word 和 PDF。
- Excel 使用项目中的《博朗费用报销单.xlsx》模板；Word 主要用于排版账单支付截图。
- 必须支持完整备份与恢复，覆盖账单和图片。

下文的状态名称、默认值和交互细节是第一版建议方案，可在开发过程中调整。

## 2. 核心使用流程

1. 出差前或出差中创建批次，填写名称、日期、目的地和事由。
2. 消费后录入金额和用途，或先把支付截图保存到批次。
3. 回来后补齐账单信息，核对金额、图片和费用分类。
4. 选择本次需要报销的账单，预览并导出报销表和图片凭证。
5. 实际向公司提交后，在 App 中标记已提交。
6. 提交后如需修改，直接编辑对应账单、重新导出，并在实际重新提交后确认，保留之前的提交版本。
7. 收到报销款后登记到账金额和日期，结清后归档。

导出文件和实际提交报销是两个独立动作。仅预览、导出或分享文件，不自动标记已提交。

## 3. 出差批次

### 3.1 批次字段

| 字段 | 要求 |
| --- | --- |
| 批次名称 | 必填，例如“苏州客户现场调试” |
| 出差起止日期 | 可以先留空，整理时补充 |
| 目的地 | 可选，支持文字记录多个地点 |
| 出差事由 | 可选，支持作为账单用途的填写参考 |
| 客户或项目 | 可选 |
| 备注 | 可选 |
| 批次状态 | 按状态规则维护 |
| 创建、修改时间 | 自动记录 |

允许同时存在多个未完成批次，不强制按日期归属账单。提前购买的车票等费用可以归入对应批次。

### 3.2 批次状态

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 记录中 | 尚未实际提交报销，涵盖费用录入、材料整理和提交准备 | 新增账单、添加图片、补齐信息、核对重复项、预览、导出、标记提交 |
| 已提交 | 至少一组账单已实际提交，尚未登记到账 | 查看提交记录、编辑账单、重新导出和提交、登记到账 |
| 部分到账 | 已收到部分报销款，批次尚未全部处理完毕 | 继续登记到账、处理剩余账单 |
| 已报销 | 所有计划报销的账单均处理完毕，应收款已结清 | 查看结果、归档 |
| 已归档 | 批次处理结束，退出日常待办列表 | 查询、查看附件、重新导出、取消归档 |

正常流程：记录中 → 已提交 → 已报销 → 已归档。

分支规则：

- 已提交后可以直接编辑账单。保存修改时显示“已修改，未重新提交”的账单提醒，批次保留“已提交”或“部分到账”；实际重新提交后更新有效申报版本和金额，再计算到账进度。
- 登记到账后，依据未完成账单和剩余应收款判断是否进入“部分到账”或“已报销”。
- 同一批次允许分次提交。即使某次提交已到账，只要还有计划报销的账单未处理，整个批次也不能自动变为“已报销”。
- 已有报销活动的批次，新增账单不清除既有提交与到账记录。
- 账单修改提醒与到账进度独立显示。例如批次处于“部分到账”时，仍可显示“2 笔已修改，未重新提交”。
- 尚未实际提交报销的批次统一保持“记录中”。补齐材料、完成检查或导出文件均不改变该状态；用户标记实际提交后才进入“已提交”。
- 归档后默认只读，需要修改时先取消归档。
- 取消出差、全部自费等批次，可以填写结束原因后直接归档，不标记为“已报销”。

材料完整度和修改提醒独立显示，例如“缺截图 2 笔、待补用途 1 笔、未提交 3 笔、已修改未重新提交 1 笔”，不只依赖一个批次状态表达所有问题。

### 3.3 批次列表与详情

- 支持按状态、日期筛选，按名称、目的地、客户或项目搜索。
- 默认优先显示未归档批次。
- 批次详情显示费用明细、材料问题、分类汇总、提交记录和到账记录。
- 金额分别展示：个人垫付净额、计划申请金额、已提交金额、已到账金额、已提交部分的待到账金额。
- “未提交的申请金额”和“已提交但未到账的金额”分开显示。

## 4. 账单记录

### 4.1 字段与草稿

| 字段 | 规则 |
| --- | --- |
| 所属批次 | 正式账单必须归属一个批次；待整理图片可暂不归属 |
| 发生时间 | 默认当天，可修改；不同于图片导入时间 |
| 费用类型 | 默认提供交通、住宿、餐饮、停车、过路、油费、采购、快递、其他 |
| 用途明细 | 简短说明费用用途，导出到模板对应列 |
| 实际支付金额 | 支持两位小数 |
| 申请报销金额 | 默认等于本人支付的净额，可修改 |
| 支付主体 | 默认本人，可标记公司直接支付；公司支付不计个人垫付 |
| 已退款金额 | 默认 0，用于退票、订单退款等情况 |
| 商户或收款方 | 可选 |
| 支付方式 | 可选，例如微信、支付宝、银行卡、现金 |
| 票据类型 | 对应模板字段，默认“支付截图”，可修改；不代表必须有发票 |
| 备注 | 可选，记录差额原因、特殊说明等 |
| 图片附件 | 支持多张，可排序 |
| 是否申请报销 | 默认是，可标记自费或不再申请并填写原因 |

允许信息不完整的草稿：可以只有金额，也可以先只有图片。导出或提交前检查时，再集中提示缺失项目。

金额精确到分。汇总时按金额值计算，避免小数精度导致明细和合计不一致。第一版默认使用人民币。

### 4.2 录入方式

- 手工快速录入：输入金额、选择类别即可保存草稿。
- 相册或系统文件选择器导入图片。
- 拍照添加图片。
- 复制已有账单的类别、用途等内容；默认不复制凭证、提交状态和到账关联，防止误报重复费用。
- 待整理收件箱：先收图片，再创建或关联账单、分配批次。

批量导入图片时提供两种明确操作：

1. 多张图片添加到同一笔账单。
2. 每张图片分别创建一笔账单草稿。

示例：住宿费 600 元，支付截图与发票图片共两张，属于一笔账单，合计仍为 600 元。

### 4.3 分类辅助字段

保持基础录入简短，按需展开以下可选内容：

| 类别 | 辅助内容 |
| --- | --- |
| 火车、飞机、长途汽车 | 起终点、乘坐日期、车次或航班 |
| 打车、市内交通 | 起终点、出行事由 |
| 住宿 | 酒店、入住和退房日期、晚数 |
| 餐饮 | 用餐日期、人数、事由 |
| 停车、过路、油费 | 行程、车牌 |
| 采购、快递、其他 | 物品或服务内容、用途 |

可根据已填字段生成用途明细建议，用户可以修改。分类辅助字段不作为第一版核心流程的完成前提。

### 4.4 管理操作

- 编辑、搜索、按日期排序、按类别和材料完整度筛选。
- 批量修改类别、选择导出、移动未提交账单到其他批次。
- 删除未提交账单时二次确认，并提供短期撤销或回收机制。
- 已提交账单的金额、用途、附件发生变化时，保留原提交快照，并显示“已修改，未重新提交”。
- 已提交账单不直接跨批次移动或永久删除；先处理撤回或更正，保留历史关系。

## 5. 图片附件

- 第一版支持常用静态图片格式，至少支持 JPEG、PNG。
- 附件默认是支付凭证，可选标注为发票、订单明细、行程截图或其他图片。
- 不要求上传发票，也不设置独立的发票开具流程。
- 支持查看大图、缩放、旋转、排序、移除和替换。
- 导入后复制到 App 管理的本地存储，不仅保存相册或外部文件的引用。
- 保存原始图片；缩略图及导出用图片与原图分开处理，保持金额、日期等文字可读。
- 清理相册中的源图后，App 内已导入图片仍可查看和导出。
- 同一张图片再次导入时提示可能重复，用户可以确认继续。
- 图片可作为多个账单的共同凭证使用，但不得因图片关联重复计入金额；一键合并导出时支持同图只输出一次，并注明关联账单编号。
- 导出或移除操作不得删除手机相册中的原图。

电子发票 PDF 直接导入不在第一版范围内，可先转成截图导入。

## 6. 报销提交与到账

### 6.1 分次提交

- 可以选择批次中的全部或部分账单提交报销。
- 提交前预览本次账单数量、申请金额、附件和检查结果。
- 标记实际提交时，记录提交日期、备注，以及对应账单和材料版本。
- 保留每次提交时的账单内容、金额、排序、图片引用及最终导出文件。
- 提交快照所需图片不得被后续编辑或清理破坏。
- 再次选择已提交账单时，明确作为原提交记录的修订进行重新提交，不创建重复费用，不叠加计算历史版本的金额。
- 同一费用只保留一条有效申报关系，历史版本用于追溯。

### 6.2 提交后的编辑、重新提交与金额调整

用户可直接编辑已提交批次内的账单，再重新导出和提交。修改图片、用途或金额采用同一套操作流程，修改原因可选填，不另设材料问题的标记和关闭流程。

操作流程：

1. 在已提交批次中打开账单，点击“编辑”。页面显示上次提交时间，允许查看上次提交内容。
2. 修改金额、用途、类别、备注或图片，保存为当前编辑版本；上次提交的快照和图片继续保留。
3. 保存后，账单显示“已修改，未重新提交”，批次详情汇总显示有多少笔账单存在未提交的修改。批次仍保持原有的“已提交”或“部分到账”状态。
4. 点击“重新导出”，默认生成该次提交的完整修订版，也可选择仅导出涉及账单的图片凭证。仅导出部分凭证时，沿用原提交中的账单编号，不重新从 01 编号。
5. 用户实际将修改后的材料交给公司后点击“已重新提交”，记录日期和可选说明，并确认本次提交的具体账单版本。
6. 已确认版本成为新的有效申报版本，清除对应账单的修改提醒；未包含在本次重新提交中的修改继续提醒。软件更新申报金额与到账进度，历史版本仍可查看。

编辑与重新提交规则：

- 编辑期间同时保留当前内容和上次提交内容；已提交金额及待到账金额仍依据当前有效申报版本计算，不提前使用尚未重新提交的修改金额。
- 只改图片、用途或备注，不改变申请金额、已到账金额和原到账记录。
- 仅编辑、导出或打开分享界面，不自动视为已重新提交。
- 修订申请金额时，预览旧金额、新金额和差额；实际重新提交确认后新申报版本生效，新旧版本不重复累计。
- 新金额与已到账金额出现冲突时提示核对，不删除或改写历史到账记录。
- 如果导出后又继续修改，确认“已重新提交”只作用于实际提交的版本；之后新增的修改仍保留提醒。
- 用户可以撤销尚未重新提交的修改，恢复上次提交内容，对应修改提醒随之清除。
- 允许多次编辑、多次重新提交，每次实际提交的版本均可追溯。

金额调整规则：

- 实际核准金额少于申请金额时，记录核减金额及原因，不覆盖原申请记录。
- 撤回或不再报销的费用保留原因，不能继续计入待到账金额。
- 申请金额超过个人垫付净额时提示核对，不擅自假定公司报销规则。

### 6.3 到账记录

用户收到报销款后手动登记实际到账，App 根据录入的金额计算进度，不自动读取银行卡或支付账户。

操作流程：

1. 在批次详情点击“登记到账”，选择对应提交记录；只有一次提交时自动选中。
2. 填写本次实际到账金额和日期，可选备注与到账截图。
3. 保存后新增一条到账记录，并更新累计到账与待到账金额。
4. 已收到款但尚未全部处理完毕时，显示“部分到账”；如有未重新提交的账单修改，额外显示修改提醒，到账金额和进度照常展示。
5. 后续每收到一笔款，再登记一次。支持“剩余款全部到账”快捷入口，预填当前剩余应收金额，由用户核对日期和金额后保存。

例如，同一次提交申请 1,500 元，且没有核减或其他未处理账单：

| 操作 | 累计到账 | 待到账 | 批次状态 |
| --- | --- | --- | --- |
| 标记已提交 | 0 元 | 1,500 元 | 已提交 |
| 登记第一笔到账 1,000 元 | 1,000 元 | 500 元 | 部分到账 |
| 登记第二笔到账 500 元 | 1,500 元 | 0 元 | 已报销 |

到账规则：

- 每笔到账保留日期、金额和备注，截图可选，不要求为了登记回款再次上传凭证。
- 默认关联本批次的一次提交；允许一笔回款分配给同批次的多次提交，分配合计必须与该笔回款一致。
- 第一版不要求把回款逐笔对应到消费账单，也不自行推断公司先报销了哪些消费；按提交记录核对总额即可。
- 一次提交允许分多次到账。
- 已提交部分的待到账金额 = 当前有效申报金额 − 已确认核减金额 − 已分配到账金额。
- 只有全部计划报销的账单处理完成、无尚未重新提交的账单修改，且剩余应收款结清，才自动标记为“已报销”。
- 如果公司明确不再报销剩余部分，由用户记录核减金额及原因。例如申请 1,500 元、到账 1,000 元、确认核减 500 元，应显示到账 1,000 元、核减 500 元、待到账 0 元，不能把未收到的 500 元登记为到账。
- 到账金额超过剩余应收金额时提示核对，不静默抹平差额。
- 修改或删除到账记录后，重新计算金额和批次状态。

第一版不处理跨批次的一笔回款自动分摊，用户可以按批次分别登记对应金额。

## 7. 提交前检查

| 检查项 | 行为 |
| --- | --- |
| 缺少金额、发生日期、类别、用途 | 指出具体账单，提供补填入口 |
| 缺少支付截图 | 提示缺凭证，允许记录例外原因后继续 |
| 没有发票 | 不提示错误、不阻止导出 |
| 可能重复的账单 | 根据相同图片或相近日期、金额、商户提示，用户决定是否保留 |
| 已提交过的账单 | 明确提示，区分新提交与修订材料 |
| 发生日期超出出差日期 | 提示核对，允许提前购票等正常情况 |
| 退款、申请金额或到账金额存在差异 | 展示差异，要求用户核对或说明 |
| 图片缺失、损坏 | 指明附件，提示修复；不能把缺图导出报告为成功 |
| 明细与汇总不一致 | 阻止生成正式报销金额，提示修复计算或数据问题 |

草稿允许保存不完整信息。正式报销表要求选中账单具有有效金额、日期、费用类型和用途；缺失项应可定位处理。

## 8. 导出需求

### 8.1 通用规则

- 支持按整个批次或选择部分账单导出。
- 默认按发生时间排序，同一天按录入顺序；允许调整本次导出顺序。
- 在同一次导出中，Excel、Word、PDF 使用一致的账单编号、顺序和金额。
- 账单编号以本次导出为范围，同时保留内部固定标识，避免后续排序导致历史材料对应关系丢失。
- 默认文件名包含批次名称、提交序号或导出时间；重导出不静默覆盖历史提交文件。
- 支持导出前预览、保存到用户指定位置和调用安卓系统分享。
- 分享操作由用户在系统界面选择目标完成。
- 导出失败时保留原始数据和已有成功文件，明确说明失败项，允许重试。

### 8.2 Excel

使用项目根目录的《博朗费用报销单.xlsx》作为原始模板，不覆盖原文件。

字段映射：

| 模板内容 | 数据来源 |
| --- | --- |
| 姓名、所属部门 | 个人设置，导出时可调整 |
| 填写日期 | 默认导出当天，可修改 |
| 发生时间 | 账单发生日期 |
| 费用类型 | 账单类别 |
| 用途明细 | 账单用途 |
| 票据类型 | 账单票据类型，默认支付截图 |
| 金额 | 本次该账单申请报销金额 |
| 备注 | 账单备注，必要时加入可对应附件的编号 |
| 合计金额、小写及人民币大写 | 按本次选中账单自动计算 |
| 单据及附件共几页 | 与本次选定的最终报销材料排版对应 |
| 原借款、应退余款 | 第一版保留模板位置，未启用借款管理时不自动填写虚构金额 |
| 报销人及审批签字区 | 保留模板位置，不代填审批签名 |

模板第一张工作表的明细区为第 5—28 行，共 24 行。超过 24 笔时采用续页方式，保持列结构、表头和签字区版式。每页小计与整份合计必须区分，不能重复累计。

第一版默认逐笔列出费用。按类别或日期合并成一行的汇总导出放在后续版本，避免原始明细与图片难以对应。

单独导出 Excel 且尚未形成固定分页的附件时，页数允许留空或手工填写，不按图片张数猜测。原模板中的空白工作表不生成额外打印页。

### 8.3 Word

- 用于生成支付截图及其他图片凭证文档。
- 默认使用 A4 纵向，包含批次名称，按账单顺序排版。
- 每笔显示编号、发生日期、用途、申请报销金额，下方排列所属图片。
- 一笔多图保持归属清晰；跨页时标注相同账单编号及续页。
- 支持每页一笔、多笔自动排版两种模式，以文字清晰为前提。
- 图片保持比例，不拉伸；长截图可单独占页或按可读区域分页，不裁掉关键内容。
- Word 中的编号与本次 Excel 明细一致。

### 8.4 PDF

支持三种导出内容：

1. 报销表。
2. 图片凭证文档。
3. 报销表与图片凭证合并成一个 PDF。

PDF 用于固定打印版式，要求中文、金额、表格边框、图片与页码正确显示，不出现截断、重叠、空白溢出页。

合并 PDF 的单据及附件页数按最终分页计算。Word 在不同查看器中可能重新分页，因此不得无条件复用 PDF 页数作为任意 Word 文件的实际页数；打印页数以对应导出预览为准，Excel 页数字段可调整。

### 8.5 材料打包

可一次选择生成 Excel、Word、PDF，并将选中格式与对应原始图片打包为 ZIP。材料包与完整数据备份分开，材料包用于提交，不承担恢复 App 数据的职责。

## 9. 本地存储与完整备份恢复

### 9.1 本地存储

- 账单、图片、设置和历史记录在本机保存。
- 核心录入、查询、状态管理和文件导出不依赖网络或服务器。
- 仅在用户选择图片、拍照、导出或恢复时请求对应系统能力。
- 未主动选择外部备份或分享时，不上传账单与图片。
- 编辑过程中及时保存草稿，App 意外关闭后能继续整理。

### 9.2 备份内容

完整备份必须包含：

- 全部批次、账单及其稳定标识。
- 全部仍被当前记录、提交历史或回收记录引用的原始附件。
- 批次状态、提交记录、材料修订记录、到账记录和金额调整。
- 已提交材料的导出文件及附件顺序。
- 个人资料、费用分类、常用内容与导出设置。
- 正在使用的报销模板及其版本。
- 备份格式版本、创建时间、文件清单和完整性校验信息。

缩略图等可重新生成的缓存可以不备份。

### 9.3 备份操作

- 提供一键完整备份，导出到用户选择且位于 App 私有目录之外的位置。
- 文件名包含备份时间，界面显示最近一次成功备份时间。
- 备份进行中应使用一致的数据快照，避免图片与账单版本错位。
- 完成后检查备份内容可读，并报告账单数、图片数及结果。
- 备份失败不更新“最近成功备份时间”，不把不完整文件当作可用备份。
- 提供可关闭的本地备份提醒；第一版采用用户主动备份，不依赖后台定时任务。

### 9.4 恢复操作

- 选择备份后，先验证文件完整性、附件清单和版本兼容性。
- 恢复前展示备份日期、批次数、账单数、图片数。
- 第一版使用完整替换恢复，不自动合并两份数据。
- 如果手机中已有数据，明确提示将替换哪些内容，恢复前先成功生成当前数据备份，再由用户确认执行替换。
- 先在临时区域完成解析与校验，全部通过后再切换到恢复结果；失败时保持原数据可用。
- 恢复后核对批次数、账单数、图片数、关键金额和记录关联关系。
- 在新设备安装后，也能用同一份完整备份恢复并重新导出材料。

## 10. 页面规划

底部主要入口建议为“出差批次、待整理、设置”。新增账单作为批次页和批次详情页的显著操作。

| 页面 | 主要内容 |
| --- | --- |
| 批次列表 | 状态筛选、搜索、未完成批次和新增入口 |
| 批次详情 | 金额、状态、材料提醒、账单列表、提交和到账入口 |
| 新增或编辑账单 | 基础字段、图片、可选分类补充字段 |
| 待整理收件箱 | 未归档图片、待补信息账单、批量整理 |
| 图片查看 | 查看原图、缩放、旋转与附件顺序 |
| 提交前检查与导出 | 选择账单、处理提醒、预览、格式与排版设置 |
| 提交记录详情 | 提交时的内容、导出文件、历次重新提交版本与到账关联 |
| 到账记录 | 新增、编辑到账及查看待到账金额 |
| 设置 | 姓名、部门、分类、默认导出选项、备份和恢复 |

第一版不需要独立的复杂统计大屏。批次列表和详情能看清未报销事项与金额即可。

## 11. 第一版与后续版本

### 第一版必需

- 安卓本地使用，无账号体系。
- 批次增删改查、状态管理和归档。
- 账单草稿、手工录入、图片导入与拍照、多图关联。
- 批量图片导入与待整理收件箱。
- 基础分类、搜索、排序和金额汇总。
- 支付截图缺失提示、基础重复检查、提交前检查。
- 按模板导出 Excel，生成图片 Word 和三种内容范围的 PDF。
- 超过 24 笔时的续页、长截图分页、跨格式编号对应。
- 分次提交、提交后编辑与重新提交、提交快照、分次到账与核减记录。
- 完整备份、校验、恢复及失败保护。

### 后续增强

- 从截图中识别金额、日期、商户等文字，识别结果经用户确认后入账；优先考虑离线处理。
- 从安卓系统分享入口直接接收图片。
- 更多分类辅助字段、常用账单模板与用途生成。
- 按类别或日期合并费用行、更多公司的报销模板。
- 原借款、补贴、外币和汇率管理。
- 跨批次回款分摊。
- 电子发票 PDF 导入与转换。
- 加密备份、用户选择的同步方案、指纹或设备认证锁定。
- 更复杂的图片相似度查重及年度统计。

### 当前不纳入范围

- 企业多人协作、在线审批、管理员后台。
- 自动登录微信或支付宝读取支付记录。
- 自动向公司发送材料或代为审批。
- 发票查验、税务计算、强制发票管理。
- 收入、投资、资产等通用财务管理。

## 12. 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 飞行模式下创建批次、录账、查看图片并导出 | 核心操作正常完成 |
| 同时管理两次出差 | 账单、金额、附件与状态互不混淆 |
| 只有截图或只有金额时保存 | 保存为草稿，后续可定位补齐 |
| 一笔 600 元账单添加支付截图和发票两张图 | 总额只增加 600 元，发票仍为可选 |
| 批量导入 5 张图片 | 能明确选择组成一笔或创建 5 笔草稿 |
| 删除相册中的源图并重启 App | 已导入的图片仍可查看和导出 |
| 录入退款或部分自费 | 垫付净额、申请金额与备注正确展示 |
| 25 笔费用导出模板 | 正确续页，无遗漏、截断或重复计入合计 |
| 多图账单及长截图导出 Word/PDF | 归属清楚、编号对应、关键文字可读 |
| 仅导出但未实际提交 | 批次不自动变为已提交 |
| 新建批次后录入费用、补齐材料、检查并导出 | 全程保持记录中，标记实际提交后才进入已提交 |
| 一个批次先提交一部分账单 | 剩余未提交账单继续可见，不重复计算已提交费用 |
| 提交后编辑账单并确认已重新提交 | 旧版本可查，新版本生效，申报总额不重复增加 |
| 已提交账单只替换截图，导出后尚未确认已重新提交 | 批次保持已提交，金额和到账记录不变，账单显示已修改未重新提交 |
| 多笔已提交账单被修改，仅重新提交其中一笔 | 清除该笔对应版本的修改提醒，其余修改继续提醒 |
| 已到账 1,000 元，仍有 500 元待到账，同时存在未重新提交的修改 | 批次保持部分到账，修改提醒与累计到账、待到账金额同时可见 |
| 修改金额但尚未实际重新提交 | 当前内容显示新金额，有效申报和待到账金额仍按上次提交版本计算 |
| 导出后继续编辑，再确认已重新提交导出的版本 | 仅导出的已提交版本生效，之后的编辑继续显示修改提醒 |
| 一次提交分两次到账 | 每次更新待到账额，最终满足条件后标记已报销 |
| 部分金额被核减 | 保留原申请、核减原因及实际到账，剩余应收正确 |
| 归档、取消归档 | 默认列表过滤正确，历史记录完整保留 |
| 全量备份后在空白安装中恢复 | 批次、账单、图片、状态、金额和历史材料一致，可再次导出 |
| 使用缺图、损坏或不兼容备份恢复 | 明确失败，现有数据不被破坏 |
| 导出或备份中途失败 | 原始记录仍完整，可重试，不误报成功 |

## 13. 开发前需落实的默认细节

这些事项不阻碍先开发核心流程，实施时以本需求的默认行为为基础：

- 姓名、所属部门在首次使用或首次导出时由用户填写，不使用虚构资料。
- 24 行以外的续页样式需要用实际模板做导出样例验证。
- 默认 Word 使用 A4 纵向、每页一笔；多笔排版作为可选模式。
- 默认人民币、本人支付、支付截图凭证、逐笔明细导出。
- Android 最低支持版本在技术方案阶段结合实际使用手机确定。
